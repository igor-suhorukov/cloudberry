# What of gpMgmt is installed, and where: a line per file, the directory
# under GPHOME it goes to, then its path under gpMgmt/, as Cloudberry's
# Makefiles install it (gpMgmt/Makefile and those of its subdirectories).
# A file the port has a copy of, src/<path> here, is installed in place of
# Cloudberry's; a path only src/ has is the port's own.  Anything under bin/
# or sbin/ is installed executable, and so is a file executable where it is.
#
# The tools the port does not install, and why:
#
#   gpexpand, gpshrink  add and remove segments; a cluster's segment count
#                       is fixed when its coordinator starts, and
#                       gp_add_segment_primary() is refused
#   gpcheckcat          checks Cloudberry's catalogs, which the port keeps
#                       as views, labels and files (gppylib/data, the
#                       catalog's JSON it reads, is not built either)
#   gppkg, gpload,      packages, loads through gpfdist, and Cloudberry's
#   gpdirtableload,     memory, log and support tools: not ported yet
#   gpmemwatcher,
#   gpmemreport,
#   gplogfilter,
#   gpcheckperf, gpsd,
#   minirepro, analyzedb,
#   gpreload, gpdemo
